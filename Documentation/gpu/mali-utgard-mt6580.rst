=====================================
MT6580 legacy Mali Utgard r8p0 driver
=====================================

``CONFIG_MALI400`` builds the GPL Arm r8p0-00dev0 Utgard driver adapted to
Linux 6.18 and the MT6580 Mali-400 MP2. It provides the original API 900
``/dev/mali`` ABI for matching proprietary EGL/GLES userspace. Proprietary
binaries are not included in this source tree.

The driver is separate from the MT6580 KMS display driver. Production
configurations must set ``CONFIG_DRM_LIMA=n``; Kconfig prevents enabling
the two GPU drivers together. A GPU device cannot be bound to both drivers.
The existing MT6580 GPU node's ``arm,mali-400`` compatible, bus/core clocks,
MFG power domain and six named interrupts are reused unchanged.

The import contains the compiled GPL core and its headers from the MT6580
vendor kernel's ``mali_r8p0-00dev0`` directory. Old MTK DVFS/GED and other
platform implementations are not built or included. The
``__malidrv_build_info.c`` file is a fixed source description; it is not
generated by the build and does not depend on the host Git checkout.

Build configuration
===================

The AIC A1260 Android kernel can select::

    CONFIG_DRM_LIMA=n
    CONFIG_MALI400=y
    # CONFIG_MALI400_DEBUG is not set

A module build is also supported when ``CONFIG_MODULES=y``. ``THIS_MODULE``
is NULL for a built-in driver; Linux's module reference helpers explicitly
accept NULL, including the references held by exported timeline/DMA fences.

``CONFIG_MALI400_DEBUG`` enables the original DDK's messages and assertions.
``mali_debug_level`` controls verbosity at runtime. High-frequency temporary
workqueue diagnostics are not part of the driver.

Linux 6.18 adaptation
=====================

* Timers, timekeeping, VMA fault/flags, PFN insertion and shrinkers use the
  current interfaces. The userspace ioctl structures and API number remain
  unchanged.
* DMA-BUF attachment mapping uses the unlocked helpers. Explicit fences use
  real ``dma_fence``, ``sync_file`` and ``dma_fence_array`` objects rather
  than casting between incompatible private and kernel layouts.
* Implicit synchronization collects ``dma_resv`` dependencies, reserves
  fence space and publishes a WRITE fence. A fence holds the module alive
  until its final reference is released. Cancellation stops callbacks
  before canceling their deferred work.
* A PP job owns its implicit-dependency waiter. It is installed before native
  sync-fence processing, including the already-signaled early-return path.
  An already-signaled native fence does not retire a separate ``dma_resv``
  dependency. Session abort retires successfully cancelled callback references
  through the same completion worker, then waits for both dependency classes.
* Native sync-file references are acquired before the timeline IRQ spinlock:
  the modern compatibility helper creates a file and may sleep. Signalling
  native timeline points holds a nonzero temporary fence reference through
  callbacks, then drops it outside the point-list lock. A callback that releases
  an aggregate fence therefore cannot recursively release its child on that
  same held lock.
* OF IRQs are resolved by name with ``platform_get_irq_byname_optional``;
  deferred clock-provider probe errors are preserved.
* Per-job and internal-domain references now feed Linux runtime PM, with
  asynchronous resume requests under DDK locks and a 100 ms autosuspend
  delay. Runtime suspend gates the GPU clocks and allows genpd to power off
  MFG; resume enables the clocks before restoring DDK groups, L2 and MMU
  state. Frequency and voltage remain firmware-selected; no PMIC rail is
  changed. Probe holds an initialization reference until registration ends.

The DDK's ``mali_kernel_linux.h`` defines ``CONFIG_PM_RUNTIME`` itself on
modern PM-enabled kernels, causing its software runtime-active flag to start
false. The platform is already active when probing, so Linux
will not issue a runtime-resume callback for its first reference. After all
GP/PP/L2 objects are registered, ``mali_pm_init_end()`` explicitly resumes
the DDK software state. Without this step jobs stay pending before hardware
submission; no GP/PP interrupt is generated.

Validation and limits
=====================

Runtime PM and shared-clock validation (2026-10-23)
--------------------------------------------------

The fixed-power results below describe the working baseline, not the new
runtime-PM trial. The trial releases the probe reference and autosuspends
after 100 ms, gating BG3D and allowing genpd to power off MFG. The user
observed a black screen, repeated reboots, and a Windows USB enumeration
failure. No UART or pstore from this trial is available yet. Further flashing
was stopped at the user's request while the failure was investigated. The
working #29 image was preserved separately.

Static analysis identifies an incomplete shared-clock dependency as a leading
suspect. MFG power-off releases TOP_MPLL_D5 (TOPCKGEN + 0x30, bit 2), while
the current SMI and USB bus gates have NULL parents. The MT6580 BSP's
mt_clkmgr.c mux tables show that CLK_MUX_SEL1[19:16] == 9 selects MPLL_D5
for SMI, and [22:20] == 4 selects MPLL_D20 for USB. MPLL_D20 is derived
from MPLL_D10, itself derived from MPLL_D5. Thus either selected consumer
can lose its source when GPU runtime PM drops the last modeled D5 reference.
The BSP also models D5 descendants for other mux selections (MSDC and NFI).
This dependency omission is established from source. The failing boot's
reset cause was not captured.

Before another power-gating trial, model the firmware-selected parent paths
and their shared references, or temporarily retain the shared D5 source until
all consumers are represented. Do not treat increasing the autosuspend delay
as a fix. A successful rebuild alone cannot validate power cycling, GPU
context restoration, or the root cause of this reboot.

The follow-up #31 test image retains only the shared D5 source with
``CLK_IS_CRITICAL``. GPU autosuspend, BG3D gating and MFG genpd power-off
remain enabled, and probe logs the firmware SMI/USB mux selections and MPLL
divider-enable register. This is a temporary guard, not a complete clock-tree
implementation: remove it after the live shared consumers and divider branches
have parent references. The #31 image restored boot and ADB, as confirmed by
the user and ``sys.boot_completed=1``. Its probe log shows SMI mux 0x9
(D5), USB mux 0x2 (UPLL_D16). Thus SMI really uses the missing shared
parent on this board; USB does not directly use D5 in this configuration.
The earlier USB enumeration failure may have been a secondary symptom.

Runtime validation started with the GPU suspended, then compiled shaders,
drew a triangle, completed ``glFinish`` and read RGBA ``0,255,0,255`` with
GL error 0. After one second the GPU was suspended again and suspended-time
accounting had advanced. Two screen-off/on cycles restored DSI video output,
with RDMA underflows and abnormal counts both zero and ADB still usable.
genpd reported MFG off, both GPU and its clock provider suspended; SPM MFG
control was 0xff12 and MFG bit 4 was clear in both power-status registers.
No new Oops, runtime-PM or power-domain failure was found in the boot log.
Full system suspend/resume with the new GPU callbacks and long-duration
stress remain unvalidated. DISP itself is still explicitly always-on.

The image is ``out/a1260-runtime-pm/boot-gpu-d5-retained.img``; the same
boot/kernel pair now supplies the canonical product output. Evidence is in
``out/a1260-runtime-pm/d5-retained-validation.txt``.

Fixed-power validation
----------------------

On the AIC A1260, the original Android 8.1 r8p0 userspace initialized EGL 1.4,
compiled/linked shaders, drew a triangle and completed ``glFinish`` and pixel
readback with RGBA ``0,255,0,255`` and no GL error. GP and PP IRQs each
advanced and completed successfully. Android native-fence export/poll and
KMS DMA-BUF/EGLImage/FBO readback were also verified. These observations
validate actual GPU work, not just driver strings or successful ioctls.

Android window rendering exposed a legacy ordering bug: an already-signaled
native fence skipped allocation of the implicit-dependency waiter, but the
dependency completion work still ran and dereferenced NULL. Installing the
job-owned waiter first preserves the real pending dependency and removes this
failure path. The session-abort path also uses the pending count instead of
manually invoking a second completion callback.

The Android 17 product now uses the original driver for SurfaceFlinger,
SystemUI, Launcher and Settings. A normal built-in-driver kernel with
``CONFIG_DEBUG_SPINLOCK=n`` reaches boot completion, draws/readbacks the
test triangle and switches between Settings and Launcher. The userspace
bridge preserves the original RGB native-handle ABI while retaining the
modern mapper and DRM display stack. The original hardware-check helper
requires this device's actual devinfo data; proprietary libraries and that
data are packaged locally outside this kernel tree.

An earlier built-in-driver boot encountered RCU stalls and display/MMC
timeouts. Its precise cause was not captured. The fence ordering/lifetime
fixes above correct identified defects; a successful short runtime does
not establish long-term stability.

Memory pressure/COW/swap stress, broader application compatibility, DVFS,
protected rendering and suspend/resume require additional validation. The
current clock/voltage policy is deliberately fixed and the existing bringup
wake lock must remain until system suspend is repaired.
